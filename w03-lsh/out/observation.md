# Week 3 · Observation

## Task 1 · Minhash and LSH

- 메모리에 안 들어가는 큰 표는 디스크에서 읽어야 한다. 문서(열)마다 다시 읽으면 표를 문서 수만큼(100만 개면 100만 번) 읽어야 해서 너무 느리다. 행을 한 번씩 읽고 버리면 표는 1번만 읽고, 기억할 것은 문서 수 × 해시 수 크기의 지문 표뿐이라 표가 아무리 커도 된다.
- R5: 서명 길이가 밴드 수로 안 나눠떨어지면 남는 행을 버리지 않고 앞쪽 밴드에 하나씩 얹었다(길이 10, 밴드 3 → [4, 3, 3]). 버리면 계산한 해시가 낭비되고 S-curve가 바뀌기 때문이다.
- S1–S4가 2/3인데 1.0으로 추정된 건 해시가 2개뿐이라 추정값이 0, 0.5, 1.0밖에 나올 수 없어서다. 해시 개수를 늘리면 차이가 줄지만 계산과 저장이 늘어난다. 오차는 1/√(해시 수)로 줄어서, 10배 정확해지려면 100배 계산해야 한다.

## Task 2 · Crossover

- 교차점은 n ≈ 600이다(600에서 brute 1.24 s, LSH 1.25 s). 측정 환경은 Intel i7-9750H, 16 GB, macOS 26.7, Python 3.9.6이다. LSH는 지문 찍는 준비 시간(약 0.9 s)이 거의 고정이라, 비교할 게 적은 작은 n에서는 준비 시간이 비교보다 커서 진다.
- 제곱 확인은 대체로 성립했다. n을 2배씩 늘릴 때 brute 시간은 평균 ×4.15였다. 크게 튄 ×4.81과 ×3.36은 n=500 한 점이 느리게 측정된 탓이고, 500을 건너뛴 250 → 1,000은 ×16.2로 4² = 16과 맞는다.
- n=8,000에서 brute force가 272초(4분 32초) 걸려 지루했다. 먼저 바닥난 것은 시간이다. 메모리는 16 GB 중 brute 90 KB, LSH 31 MB밖에 쓰지 않았다.

## Task 3 · Comparing far less

- n = 100, b = 25(r = 4)로 step = (1/25)^(1/4) = 0.447이며, 기준 0.6보다 낮게 뒀다. 진짜 쌍 중 가장 약한 쌍이 0.622라 step을 0.6에 두면 기준 근처 쌍을 절반쯤 놓치지만, 0.447이면 P(0.622) = 1 − (1 − 0.622⁴)²⁵ = 98.2%로 거의 다 잡는다. 대신 비교가 늘 수 있는데, 이번엔 126번 중 헛비교가 5번뿐이었다(recall 100%, 비교 99.99% 감소).
- step을 올리니 recall이 7%까지 떨어졌고 비교 수는 줄었다. 밴드 25 → 10 → 5(step 0.447 → 0.794 → 0.923)에서 비교는 126 → 58 → 9, recall은 100% → 47.9% → 7.4%였다.
- 해싱을 세지 않는 건 문서가 적을 때 불공정하다. 지문 찍는 시간이 대부분이라서, n=125에서 LSH는 비교 0번으로 점수는 만점이지만 실제로는 1.00초로 brute force(0.06초)보다 약 18배 느렸다.
